# BMS-STM32F103

基于 **STM32F103 + TI BQ76920** 的 5 节锂电池管理系统（BMS），FreeRTOS 多任务调度，OLED 实时显示。项目按尚硅谷教程体系从零实现，覆盖 AFE 驱动、硬件保护配置、电量计与均衡控制。

## 功能特性

- **AFE 驱动**：BQ76920 I2C 通信，逐字节 CRC-8（多项式 0x07）校验
- **硬件保护配置**：短路（SCD）/ 过流（OCD）/ 过压（OV）/ 欠压（UV）阈值与延时全部可配，写入前经出厂校准值换算并做 14 位窗口限幅
- **数据采集**：5 节单体电压、电池组总压、充放电电流、电芯温度（NTC）
- **SOC 估算**：101 点 OCV 查表 + 分段温度补偿
- **均衡控制**：压差触发的均衡决策，含相邻电芯互斥保护（手册绝对最大额定值约束）
- **OLED 显示**：SSD1306 驱动，显示电芯电压 / 总压 / SOC

## 硬件平台

| 部件 | 型号 / 参数 | 说明 |
|---|---|---|
| 主控 | STM32F103（Cortex-M3） | CubeMX 生成 HAL 框架 |
| AFE | TI BQ76920（3~5 串） | I2C 从机地址 0x08，挂 I2C2 |
| 检流电阻 | 5 mΩ | 电流分辨率 8.44 µV ÷ 5 mΩ ≈ **1.69 mA/LSB** |
| 电芯 | 5 串锂电 | 外部均衡电路（NMOS + 均衡电阻） |
| 温度 | 10 kΩ NTC（MF52A103F3950） | 接 AFE 的 TS1 引脚 |
| 显示 | 0.96" OLED（SSD1306） | I2C 地址 0x78，与 AFE 共用 I2C2 总线 |

## 软件架构

```
┌─────────────────────────────────────────────┐
│  App 层    App_Main.c — FreeRTOS 任务调度     │
│            bms_task（采集+均衡）/ oled_task   │
├─────────────────────────────────────────────┤
│  Com 层    Com_BQ769.c — 算法与查表           │
│            电阻→温度、电压→SOC（OCV 表）       │
├─────────────────────────────────────────────┤
│  Int 层    Int_BMS.c    — BQ76920 业务驱动    │
│            Int_OLED.c   — SSD1306 驱动        │
│            Int_Screen.c — 界面绘制            │
│            Int_BQ769_BSP.h — 寄存器/位域定义  │
├─────────────────────────────────────────────┤
│  Core 层   CubeMX 生成：GPIO / I2C2 / USART  │
│            HAL + FreeRTOS 内核                │
└─────────────────────────────────────────────┘
        │ I2C2 (PB10/PB11, 100kHz) │ UART1 调试串口
   BQ76920 ── 5节电芯/检流电阻/NTC      OLED
```

分层原则：`Int` 层只面向寄存器和总线，`Com` 层只做纯算法（输入数值、输出结果，不碰硬件），`App` 层只管任务节奏。换一颗 AFE 只动 `Int/BMS`，换显示方案只动 `Int/SCREEN`。

## 关键技术点

### 1. I2C + CRC-8 可靠通信

BQ76920 的 I2C 读时序要求每个寄存器字节后跟一个 CRC 字节（多项式 0x07，初值 0），驱动按 `[数据][CRC][数据][CRC]...` 逐段校验，连续读取 N 个寄存器只需给一次起始地址。ADC 校准参数、电压、电流全部经 CRC 验证后才采用。

### 2. 保护参数的出厂校准换算

OV/UV 阈值不能直接填电压，须按手册算法四步换算：

```
GAIN  = 365 + ADCGAIN<4:0>      （µV/LSB，出厂 365~396）
OFFSET = ADCOFFSET               （mV，有符号补码）
OV_TRIP_FULL = (OV - OFFSET) / GAIN        → 14 位 LSB 值
写入值 = OV_TRIP_FULL >> 4 & 0xFF          （取中间 8 位）
```

14 位值有硬件窗口约束（UV：`0x1000~0x1FF0`，OV：`0x2008~0x2FF8`），高 2 位是芯片解析前缀。**超出窗口时右移 4 位会丢掉前缀，欠压点会从 3.2 V 掉到 1.6 V 才触发**——驱动对换算结果做了限幅，这是手册没有明说、只能从寄存器格式推导出来的坑。

实际保护配置（5 mΩ 检流电阻）：

| 保护 | 阈值 | 延时 |
|---|---|---|
| SCD 短路 | 89 mV ≈ 17.8 A | 100 µs |
| OCD 过流 | 78 mV ≈ 15.6 A | 20 ms |
| OV 过压 | 4.20 V | 8 s |
| UV 欠压 | 3.20 V | 8 s |

### 3. SOC 查表 + 温度补偿

- 101 点 OCV-SOC 曲线表（3282~4185 mV），线性查找返回整数 SOC
- 5 节单体 SOC 取均值作为整组电量
- 分段温度补偿：0~40 °C 按 -0.5%/°C（相对 25 °C）修正，低温/高温段叠加额外系数
- 查表函数实现为**无状态**线性查找——原状态机版本在电压跌破表底时会把搜索索引锁死在 0，后续所有电芯都被污染成 0%

### 4. 均衡决策算法

不均衡不放电，核心是一组前置守卫 + 相邻互斥：

- **守卫条件**（任一满足则跳过本轮）：最高节 > 4.2 V / 最低节 < 3.2 V / 压差 < 30 mV（无需均衡）/ 压差 > 1 V（电芯故障，均衡救不了）/ 温度 > 55 °C
- **互斥规则**：手册规定相邻电芯（CBx 与 CBx+1）禁止同时开启，否则 cell pin 超出绝对最大额定值。算法对相邻冲突对按电压高低裁决，只保留电压高的一节
- 硬件为外部均衡（NMOS + 均衡电阻），由 `CELLBAL1` 寄存器的 CB1~CB5 位控制

### 5. 模式管理

上电走 `SHIP → NORMAL` 模式切换：BQ76920 出厂处于 SHIP 模式（µA 级功耗），须通过寄存器写序列唤醒；`CELLBAL` 位在 XREADY 置位或模式切换时会被硬件自动清零，均衡状态不能只写一次。

## 编译与烧录

1. **Keil MDK** 打开 `MDK-ARM/atguigu-project-bms.uvprojx`（ARMCC5 编译器）
2. Build（0 Error）→ Download（ST-Link / J-Link，目标 STM32F103）
3. 调试串口 UART1，波特率见 `Core/Src/usart.c`；上电先打印 `BMS Project Start`，随后输出电芯电压 / 总压 / 电流 / 温度 / SOC
